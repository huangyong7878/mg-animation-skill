# 事实核验协议（面向调用本 Skill 的 AI Agent）

请不要将 `scripts/factcheck.py` 的 PASS 当作事实本身已被证实；它只是一道**结构/引用证据门禁**。

1. 从每个事实镜头中抽取可独立检验的断言（数字、年份、比较、地理范围、制度分类、因果结论等），分别生成唯一 `claim_id`。
2. 对每条断言优先查找第一手资料：政府公告、原始研究、统计机构、企业定期报告、原始访谈。记录 URL、发布日期、资料对应日期、精确可定位的引文、数据口径。重要结论应尽可能交叉验证。
3. 检查引文是否真的支持断言的含义，特别警惕否定、预测与事实混淆、量纲误用、时间范围错配、样本与总体混淆。
4. 没有足够证据的断言应保持 `status: unverified`，或将内容改成有根据的限定表述。不要把「需要核实」直接变成 `verified`。
5. 把研究结果写入顶层 `claims`，场景记录 `claim_ids`。运行 `scripts/validate.py`；有网络时进一步执行 `scripts/factcheck.py FILE --fetch-sources` 确认来源页含引文；对于 PDF、JS 动态页或付费墙，自动检查失败不意味着引文为假，需手动确认并保存截图/副本。
6. 对健康、法律、投资等高风险内容，让熟悉领域的审核人员检查结论；审核通过也要在视频中标注数据日期和信息来源。

注意：引文核验程序只读取公开 URL，不访问个人资料。不要将私有网络地址、内部密钥或凭证填进 `claims`。
