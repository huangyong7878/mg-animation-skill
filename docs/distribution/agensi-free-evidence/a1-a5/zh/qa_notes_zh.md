# QA 说明 — 为什么天空是蓝色的

## 1. 假设

- **采用的默认值：** 语言为简报指定的简体中文；画布 960 × 540（16:9），24 fps；总时长 20.0 秒（简报硬性要求）；旁白仅做文字时间规划，不生成音频；风格为暖色纸张信息图；默认转场 `crossfade` 0.6 s，s1→s2 使用 `wipe_left` 0.6 s，s2→s3 使用 `slide_left` 0.6 s。
- **镜头分配：** s1 0.0–6.0 s，s2 6.0–12.0 s，s3 12.0–20.0 s，共 3 个镜头。
- **简报未提供：** 图片、图标、字体、音乐资产、TTS 音色或语速、任何独立来源。因此不使用 `image` 节点，全部画面由文字、卡片、箭头、表格和时间线构成。
- **时间口径：** 动画和旁白 offset 都是场景内相对时间；旁白时长按中文 3.5–5 字/秒估算，不是测量值。

## 2. 事实状态

- **用户提供（来自简报），未独立核实：**
  1. 阳光包含不同颜色的光。
  2. 大气中的分子会使短波蓝光比红光散射得更强。
  3. 因此我们从各个方向看到蓝光（白天天空偏蓝）。
  4. 日落时阳光要穿过更厚的大气层。
  5. 蓝光大多被散射掉，剩下的红橙光让天空看起来偏红。
- **画面概括句：** s1 底部提示“不同颜色的光，被散射的程度不同”是上述第 2 条的概括；s2 结论卡“短波蓝光更容易被散射，白天天空偏蓝”对应第 2、3 条。两句同样按用户提供/一般常识处理，未独立核实。
- **独立核实：** 无（none）。本次没有查阅任何外部来源，也没有记录 URL、引文或复核日期。
- **未核实/省略：** 简报中的“人眼对蓝光最敏感”没有提供来源。它没有出现在分镜画面或旁白中，也没有写入 Scene JSON 的 `claims`。如果用户要求加入，只能先作为 `unverified` 声明处理；而 v2.1 的默认 claim gate 要求每条 claim 都是 `verified`、带 http(s) URL 和至少 8 个字符的引文，因此在补齐来源之前，整个文档会被拒绝。
- **关于空 claims 数组：** Scene JSON 使用 `claims: []`，三个场景均为 `factual: false`。这只表示没有登记任何声明，**不表示**内容已经核实；空数组不能被当作证据，也不能被描述为“已通过事实核查”。
- **可发布性：** 本稿是文本预制作草稿，**尚不能作为已核实视频发布**（not ready to publish as a verified video）。画面中的科学表述属于用户提供/一般常识，需要人工复核后才适合公开发布。

## 3. 时间风险

- 估算总语音 9.0–12.9 s，画布 20.0 s，整体有余量。
- 分镜余量：n1 估计 2.0–2.9 s，场景 6.0 s；n2 估计 2.8–4.0 s，场景 6.0 s；n3 估计 4.2–6.0 s，场景 8.0 s。
- 最紧的是 s3/n3：offset 0.5 s，按最慢估算 6.0 s，结束于 18.5 s；距画布结束 1.5 s，场景级余量约 20–25%。慢速 TTS 下仍建议复核。
- **重叠检查：** n1 绝对起点 0.4 s，n2 6.4 s，n3 12.5 s；按估算最长时长，结束点分别不超过 3.3 s、10.4 s、18.5 s，互不重叠，总旁白不超过 20.0 s。
- 所有语音时长均为估算，未运行 TTS；实际 TTS 测量值优先，届时需要回改分镜和 JSON。
